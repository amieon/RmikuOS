# α 缩放调度旋钮的自适应控制：五类方法家族的受控对照研究

**平台**：RmikuOS（从零实现的双架构教学内核，RISC-V 64 / LoongArch 64）
  
**实验环境**：QEMU virt 模拟（riscv64，标定见 §2.5）
  

---

## 摘要

现代操作系统常同时承载两类互斥需求：对延迟敏感的 **deadline 任务**（周期作业，错过截止即失败）与吞吐导向的**多线程计算任务**（尽力而为）。在按权重分配 CPU 的调度器中，两者通过缩放因子 **α** 调节——α 越大，多线程任务的 CPU 份额越高，但 deadline 任务的迟到（miss）越严重；**最优 α 随负载动态漂移，无法离线确定**，因而需要在线自适应控制器。

本文在自研内核 RmikuOS 上实现了 **α-scaled 调度**（多线程任务的有效票数按线程数的 α 次幂缩放），并把**五个方法家族**的自适应控制器——启发式（AIMD）、网络协议（CUBIC）、深度学习优化器（SGD-M / RMSProp / AdaGrad / AdamW）、经典控制（增量式 PI）、在线学习（滑窗 UCB）——放在**同一批次、同一主机、同一 QEMU 参数**下对撞（21 种配置 × 3 种相位比例 × 3 重复 = 189 次运行）。同批成立由 `burn/run`（迭代/tick）同 ratio 内跨模式落窄带验证（25/25: 8.4~9.2；40/10: 8.9~9.7；10/40: 8.4~9.4；它对主机速度敏感，也随负载形态小幅系统漂移，§2.4）。

**核心发现**（与朴素直觉相反）：

1. **控制器落点由「信号结构 + 先验/探索」决定，与更新公式复杂度无关**。同起点 α0=50、负载各半（25/25）时，五类的稳态 α 排成一条轴：UCB 6.7 → AdamW 24.9 → PI 36.3 → AIMD 42.0 → CUBIC 46.4 → 无 decay 优化器 57~72；该排序在另外两个相位比例下会压缩乃至乱序（10/40 下 UCB 崩至 0.2），但漂移的形态本身仍由先验/信号结构刻画（§5.2.2）。区分它们的是两件事：信号是否**吞吐盲**（只罚 miss 不奖吞吐），以及有没有**非零先验或显式探索**（decay 锚点 / +5 试探 / bandit 探索 bonus）。
2. **朴素启发式 AIMD 帕累托最优**：aimd50 miss 6.9%、吞吐 964k，aimd100 更以 1,031k（+10.7%）成为吞吐最高的自适应控制器且 miss 最低（6.8%），家族整体支配了 AdamW（7.5%、873k）与其余所有自适应控制器——但「梯度法」并非铁板一块：**带 decay 先验的 AdamW** 吞吐低 ~10% **且 miss 还高**（7.5% vs 6.9%，双输而非「追平」）；**无先验的三兄弟 SGD-M / RMSProp / AdaGrad 的 miss 飙至 32~65%**。同一算法家族内部的这次分裂，正是「先验而非复杂度决定落点」的直接证据。
3. **PI 的稳态与起点非单调**（pid0→0.3、pid50→36.3、pid100→2.3）：同一个控制器存在 α=0（钳位边界）与 α≈36（稳定平衡）两个吸引子，起点决定落入哪个——微分项在相位阶跃处的过冲不可逆，因为 α=0 处误差信号被控制器亲手消灭。
4. **跨批次实验的隐蔽陷阱**：`ai_burn` 依赖主机速度，跨批次比较会被污染达 ~20%（旧数据 AdamW 虚高正是此因）。本文提出以 `burn/run` 作为同批 QC 指标，并以「同一批次」作为方法间对比的必要条件。

**结论**：在 deadline 调度这个「单边悬崖」地形上，决定控制器优劣的不是优化方法的复杂度，而是**领域先验是否被编码进动作空间**——AIMD 的非对称动作（快撤/慢爬/冻结）恰好匹配了「代价全在高 α 一侧」的地形；而通用优化器因缺乏该先验而漂高或饱和。这为「机器学习优化器能否用于内核资源控制」提供了一个更冷静的答案：**能站上同一舞台，但吃不到启发式的先验。**

## 1 引言

### 1.1 问题背景

现代计算负载（尤其 AI 训练/推理）由大量轻量线程组成，天然适配「按线程数加权」的 CPU 分配；而实时性任务（控制回路、媒体处理、监控）以周期作业形式运行，要求每个作业在 deadline 前完成。两者在同一调度器上竞争时存在根本张力：

- 多线程任务希望**按线程数获取 CPU**——线程越多，份额越大；
- deadline 任务希望**稳定、可预期地获得 CPU**——任何突发抢占都造成 miss。

经典的 stride/lottery 调度只能表达「固定权重」，无法表达「随运行状态变化」的权重。

### 1.2 α 旋钮：公平性-吞吐的连续权衡

RmikuOS 实现 **α-scaled 调度**：多线程任务的有效票数按 `scale(线程数, α)` 缩放，α ∈ [0,100]：

- **α=0**：多线程任务按 1 票/线程计，与其线程数无关——deadline 稳定，miss 低但吞吐受限；
- **α=100**：多线程任务按线程数线性放大票数——吞吐高但 miss 爆炸；
- 中间值连续权衡。

实验确认该权衡是「悬崖式」的（§5.1）：miss 对 α 的响应在中等负载下近乎阶跃（fixed25 仅 ~3%，fixed50 即 ~42%），**最优 α 落在极窄区间，且随负载迁移**。

### 1.3 自适应控制问题

由于最优 α 随负载动态漂移（轻负载期可冲高吃满空闲 CPU，重负载期必须退避保护 deadline），固定 α 无法胜任。本文研究**在线自适应控制器**：每个调度窗口结束时，依据观测反馈决定下一个窗口的 α。

### 1.4 贡献

- **系统**：在从零实现的内核中实现 α-scaled 调度与五类自适应控制器（全部定点运算，无浮点），并搭建可复现的实验框架 schedlab；
- **方法**：提出「同一批次」的对照方法论，以 `burn/run` 作为跨方法可比性的 QC 判据，消除跨批次主机漂移对 `ai_burn` 的污染（§2.6）；
- **发现**：五类方法家族的稳态落点可由「信号结构 + 先验/探索」两个维度解释；AIMD 帕累托最优，梯度法/控制法/学习法均未超越启发式；
- **数据**：189 runs 同批统一矩阵、原始 CSV、统计脚本、图表全部开源（`logs/sched/`），可完全复现。

## 2 系统模型

### 2.1 平台：RmikuOS

RmikuOS 是从零实现的教学型操作系统内核，支持 RISC-V 64 与 LoongArch 64 双架构，含进程/线程、虚拟内存、VFS、virtio 驱动、自研 TCP/IP 协议栈等完整子系统。调度实验运行在 riscv64 / QEMU virt / SMP 单核环境。

### 2.2 stride 调度与 tickets

RmikuOS 采用 **stride scheduling** 公平性内核：每线程持 `tickets`（权重），调度器维护 stride pass 值，每次调度选出 pass 最小者并按其 stride 递增，保证 CPU 份额与 tickets 成正比（实验标定：ctrl 65.3% 与 tickets 占比 66.7% 一致）。

### 2.3 α-scaled 调度

α-scaled 调度在 stride 之上叠加**负载缩放因子**：多线程任务的每线程票数乘以

```
scale(n, α) = floor(n^(α/100))          # 纯整数幂，α ∈ [0,100]
```

- 单线程任务（ctrl）：票数不变；
- 多线程任务（ai）：每线程票数按 `scale(n, α)` 缩放。

实现要点：全程整数运算（定点 ×1024），热路径缓存 scale 结果，`set_sched_alpha` 系统调用在线修改 α。floor 阶梯的精确解析模型（「scale 是 n^(α/100) 的 floor 阶梯函数」）已由实验验证，误差 0.16（对比连续模型 0.54），是本文 α 机制可精确建模的基础。

### 2.4 指标定义

| 指标                   | 定义                        | 含义                |
| -------------------- | ------------------------- | ----------------- |
| **miss%**            | 周期作业中错过 deadline 的百分比     | deadline 健康度，越低越好 |
| **late / tardiness** | 错过 deadline 的作业平均迟到量      | 错过严重程度            |
| **ai_burn**          | 多线程任务的有效产出（burn 迭代计数）     | 吞吐，越高越好           |
| **ai_run**           | ai 的 CPU 分配时间（tick 计数）    | 区分「分到 CPU」与「干出活」  |
| **burn/run**         | ai_burn / ai_run（迭代/tick） | 主机速度 + 负载形态标尺 / 同 ratio 跨模式 QC    |
| **α_steady**         | 测量段轨迹**后半段**的平均 α（窗口数 > 10 时采用） | 控制器的稳态工作点         |

### 2.5 时间基准标定

| 项目           | 结果                               | 判定    |
| ------------ | -------------------------------- | ----- |
| tick ↔ 时间线性度 | slope=13,984.5 us/tick，R²=1.0000 | ✅ 线性  |
| burn 负载线性度   | 400k iters≈2.72 tick，偏差 6%       | ✅ 线性  |
| 跨实验漂移        | exp10 批次运行前后 us/tick 变化 0%               | ✅ 无漂移 |

> 教训：标定对宿主负载极其敏感。首次标定在宿主高负载下（1 tick=66.44ms），数据作废；清理环境后重标定才得到干净结果——模拟器上的调度实验必须把「宿主干扰」当作一等误差源。

### 2.6 跨批次漂移与同批实验的必要性（方法论贡献）

`ai_burn` 是「burn 迭代次数」，其数值 = 每 tick 内 QEMU 执行的指令数 × ai 分到的 tick 数。**前者依赖主机速度**：同一份二进制在不同主机/不同负载下，`burn/run`（迭代/tick）可差 ~10%（实测旧批次 9.55 vs 新批次 8.66）。

这一点的破坏性在一次「数据对不上」的排查中被证实：旧 exp6 的 AdamW `ai_burn` ~1.0M，新批次同配置仅 ~800k（−18%），一度疑似 bug；分解后确认 = `ai_run` −10%（调度噪声）× `burn/run` −9%（主机变慢），**完全不是控制器差异**。

结论与对策：

1. `ai_run`（tick 计数）是主机无关的可靠指标；`ai_burn`（迭代计数）跨批次不可比；
2. 方法间对比必须**同批**——本文的 exp10 统一矩阵即为此设计，并以「`burn/run` **同 ratio 内**跨模式落在窄带」作为同批成立的 QC 判据。注意 `burn/run` 还随 ratio 小幅系统漂移（25/25: 8.4~9.2；40/10: 8.9~9.7；10/40: 8.4~9.4，同批同主机）——它不是纯主机速度标尺，故方法对比一律在同 ratio 内进行。

## 3 问题定义

**在线 α 调节问题**：给定窗口序列 w=1,2,…,W，每窗口结束时控制器依据反馈向量决定 α\_{w+1} ∈ [0,100]：

```
minimize   Σ_w miss_w        (deadline 健康度)
maximize   Σ_w burn_w        (吞吐)
```

两者存在根本权衡（§5.1），实际优化带权目标。**五类控制器给出了五种求解哲学**（§4.2）：本文的对照目标不是「谁 miss 最低」，而是「在同一个权衡地形上，各方法家族停在哪、为什么」。

## 4 方法与实验设计

### 4.1 schedlab 实验框架

- **负载注册**：ctrl（周期 deadline 作业，in-parent）、ai（多线程 phased-spin）、log（低权重 spin）；
- **相位机制**：L-H-L-H 四段（轻-重-轻-重），`sl_l_ratio_permil` 控制 L 段占比；
- **统一输出**：每窗口输出 `W/D/A/S` 行，策略输出 `A,win,before,after,action` 行（优化器家族为 8 列，追加 loss/g/step/decay 供分量分解）；
- **统计脚本**：流式解析（`compute_file`，~300 万行不驻内存），输出汇总表与图表。

### 4.2 五类自适应控制器

#### 4.2.1 AIMD（加性增 / 乘性减）——启发式

```
late ≥ 25:  α ← α × backoff       # 迟到严重，乘性退避
late ≤ 0 :  连续 2 窗则 α ← α + 5  # 无迟到，显式试探爬升
0<late<25:  冻结（gray）           # 不健康但未危险，干等
```

- 反馈信号：1-bit（是否迟到）；动作空间**非对称**（快撤 ×0.8、慢爬 +5、gray 冻结）。

#### 4.2.2 CUBIC——网络协议（RFC 8312 思路）

```
退避:   α ← α × 0.7, 记 w_max = 退避前 α
爬升:   W(t) = C·(t − K)³ + w_max,  K = cbrt(w_max(1−β)/C)
```

- 判据与 AIMD 相同（late ≥ 25），唯一差异是**爬升曲线**：远离 w_max 快速收复、逼近减速缓行；**没有 gray 冻结**——late < 25 的每一窗都在爬。

#### 4.2.3 优化器家族（SGD-M / RMSProp / AdaGrad / AdamW）——深度优化

共用 SPSA 梯度估计与同一 loss，只换更新公式：

```
loss = miss_per_1000 + 平均迟到×1000        (封顶 4000)
SPSA: probe = α ± δ (δ=5),  g ≈ Δloss / (2·δ·方向)
SGD-M  : m=0.9m+0.1g,        step = lr·m / G_REF
RMSProp: v=0.99v+0.01g²,     step = lr·g / √v
AdaGrad: v+=g²(不衰减),      step = lr·g / √v
AdamW  : 动量+自适应,         α ← α − step + decay,  decay 拉回 target=25
```

三兄弟**结构上无 decay**；AdamW 的 decay 是唯一把 α 锚定在 25 的先验。

#### 4.2.4 PI（增量式）——经典控制

```
e = late_delta − target(=10)
Δα = −(kp·Δe + ki·e)/1024,   kp=150, ki=64
α ∈ [0,100] 钳位（anti-windup）
```

纯反馈，无先验、无探索；α 本身即积分器。

#### 4.2.5 SW-UCB——在线学习

α 离散成 11 臂（0,10,…,100），每窗整臂调度：

```
reward = 10000 − loss          # 只罚 miss，不奖吞吐
选臂 = mean_i + c·√(2·ln t / n_i),  τ=32 滑窗
```

#### 4.2.6 五类的信号结构对比（本文的核心分析框架）

| 控制器                   | 信号                | 非零先验 / 探索          | 吞吐项     |
| --------------------- | ----------------- | ------------------ | ------- |
| AIMD                  | late 阈值(1-bit)    | 显式 +5 试探 + gray 冻结 | 有（试探爬升） |
| CUBIC                 | late 阈值(1-bit)    | 无（连续爬，无冻结）         | 有（但过冲）  |
| SGD-M/RMSProp/AdaGrad | loss(连续)          | 无 decay            | 无       |
| AdamW                 | loss(连续)          | decay 先验(锚 25)     | 无       |
| PI                    | e = late−target   | 无                  | 无       |
| UCB                   | reward=10000−loss | bandit 探索 bonus    | 无       |

**本文的核心假设（由实验验证）**：稳态落点由「信号是否吞吐盲」与「有无非零先验/探索」两列决定，而与「更新公式复杂度」无关。

## 5 结果

### 5.1 exp00-02：问题与 α 机制

- **exp00**：无自适应（公平分配）时 ctrl miss 100%——50 线程的 ai 把周期作业完全挤死，必须引入 α 旋钮。
- **exp01**：α 从 0 到 100 扫描，`eff_tickets` 随 α 平滑单调增长——α 是连续、可预测的旋钮。
- **exp02**：miss 的悬崖响应——medium 配置 fixed0/25 仅 ~1%，fixed50 跳至 53%，fixed75 85%；最优 α 落在极窄区间且随负载迁移。

### 5.2 exp10：五流派同批统一矩阵（核心，189 runs）

同批 QC：`burn/run` 每个 ratio 内跨模式落窄带（25/25: 8.4~9.2；40/10: 8.9~9.7；10/40: 8.4~9.4，远窄于跨批次的 ~9.5 vs ~8.7），**同批成立，`ai_burn` 可在同 ratio 内直接跨方法比较**。

#### 5.2.2 发现 1：五流派落点轴 = 信号结构 + 先验/探索

同起点 α0=50（ratio 25/25），稳态 α 从低到高：

| 控制器                  | α_steady | miss%   | 非零先验/探索                 |
| -------------------- | -------- | ------- | ----------------------- |
| ucb                  | 6.7      | 8.1     | bandit 探索（但 reward 吞吐盲） |
| adamw                | 24.9     | 7.5     | decay 先验锚 25            |
| pid50                | 36.3     | 21.7    | 无                       |
| aimd                 | 42.0     | **6.9** | 显式 +5 试探 + gray 冻结      |
| cubic                | 46.4     | 21.6    | 无冻结，连续爬                 |
| rmsprop/sgdm/adagrad | 57~72    | 32~51   | 无 decay                 |

**落点从 6.7 排到 72（25/25），与「更新公式复杂度」无关，与「信号结构 + 先验/探索」清晰对应**：有非零先验/探索的（UCB、AdamW、AIMD）落在 6.7~42 的稳定区，没有的（CUBIC、三兄弟）漂高，PI 则落入双吸引子（§5.2.4）。

**这条轴不是 25/25 专属的花样，但也不是普适常数**——跨 ratio 的落点漂移本身就是「信号结构 + 先验/探索」的第二份证据：

| ratio | 轴的状态 | 关键变化 |
| --- | --- | --- |
| 40/10 | 保序、整体右移 | UCB 26.0 ≈ AdamW 27.0、PI 40.0、AIMD 47~53、三兄弟 51~59——轻载占比大，全员敢往高 α 住，带先验者仍居前 |
| 10/40 | **乱序** | UCB 崩至 0.2、pid100→8.6、AIMD 家族压到 16.9~24.8 与 AdamW（23.8~29.0）交叠、三兄弟反而 42~68 |

机制：相位越偏重载，miss 信号越「响」，吞吐盲的控制器被压向低 α；但**漂移的幅度由先验决定**——握有 decay 锚点的 AdamW 落点最稳（三 ratio 全部落在 21.5~30.6），纯信号驱动的 UCB 摆动最大（0.2~26.0）。落点的绝对值随负载变，落点漂移的形态不变：先验强的锚得住，信号驱动的被负载牵着走。

#### 5.2.3 发现 2：AIMD 帕累托最优，支配 AdamW

同起点 α0=50 直接对比：

|         | miss%   | ai_burn     | 结论   |
| ------- | ------- | ----------- | ---- |
| aimd50  | **6.9** | **963,713** | 严格占优 |
| adamw50 | 7.5     | 873,358     | 被支配  |

同起点对比在 25/25 与 40/10 均成立（40/10：aimd50 6.9→7.3；adamw50 7.5→8.0）。10/40 方向一致但须谨慎：逐 rep 看，该 ratio 下所有自适应控制器的单 run miss 横跨 10~44%（如 adamw 三起点 9 个 rep 落在 10.6~43.9），组内方差远大于组间均值差——n=3 的均值在高方差负载下不构成强证据，10/40 只能作为方向性旁证。**带 decay 先验的 AdamW 被启发式双指标压制——miss 更高（7.5% vs 6.9%）且吞吐低 ~10%，没有在任何指标上反超；同家族无先验的三兄弟 miss 高达 32~51%（25/25），10/40 下 rmsprop 达 65%**——优化器家族内部发生分裂，分水岭只有一行 decay（机制见 §6.3）。 这与 v0.1 稿「AdamW 全面碾压」的结论相反——旧结论是跨批次污染的假象：旧 AdamW（exp06）跑在更快的主机上，而对比对象 AIMD/fixed 复用的是不同 total（96k vs 240k ticks）的 exp4/5 数据，两套数字本就不在同一把尺子上（§2.6）。

**对比边界：fixed25 是后验 oracle，不是同台对手。**静态负载下后验最优的 fixed25 miss 仅 2.4~3.5%，优于包括 AIMD 在内的一切自适应控制器（25/25 上 aimd50 的 miss 是它的 ~3 倍）。但 fixed25 的最优是「先知式」的：它预知 ratio=25/25 才敢钉在 25——负载迁移（exp02/exp04）时 fixed 无法跟随，这正是自适应控制器存在的理由。自适应的回报体现在吞吐：aimd50 的 burn 964k 高于 fixed25 的 931k（25/25），即以 +4.5pp 的 miss 换取 ~+3.5% 的吞吐与跨负载迁移能力。因此本节「AIMD 帕累托最优」的量化范围是**同为自适应控制器**的内部比较：exp10 回答的是「不知道负载时谁最优」，答案是 AIMD；「知道负载时该不该用自适应」是另一个问题，答案是 miss 上不值得、吞吐上仍有盈余。

#### 5.2.4 发现 3：PI 的稳态与起点非单调

|                 | pid0 | pid50    | pid100 |
| --------------- | ---- | -------- | ------ |
| α_steady（25/25） | 0.3  | **36.3** | 2.3    |
| miss%           | 8.0  | 21.7     | 23.2   |

起点 50 的稳态比起点 100 **还高**——非单调。机制（§6.4）：PI 存在 α=0（钳位边界）与 α≈36（稳定平衡）两个吸引子；pid100 从 100 往下砸，微分项冲量过大、越过平衡点直接砸穿到 0，而 α=0 处迟到地板 > target=10 → e>0 永续 → 不可逆地停在 0。pid50 冲量小，恰好落在 α≈36 平衡点。

#### 5.2.5 发现 4：miss-吞吐 tradeoff 的定量账

本实验的核心命题就是这笔交易：**动态调 α，以少量 miss 为代价换吞吐**。以后验 oracle fixed25 为基准，兑换率 exchange = Δburn% / Δmiss_pp（每付 1pp miss 换回多少 % 吞吐），25/25 上关键模式的账目：

| 模式      | burn        | Δburn% | Δmiss(pp) | exch   | 评价               |
| ------- | ----------- | ------ | --------- | ------ | ---------------- |
| aimd100 | **1,030,723** | **+10.7** | +4.4      | **+2.43** | 全场最划算             |
| aimd50  | 963,713     | +3.5   | +4.5      | +0.78  | 正收益              |
| aimd0   | 935,707     | +0.5   | +4.5      | +0.11  | 几乎白付             |
| adamw50 | 873,358     | **−6.2** | +5.1      | −1.21  | 双输（25/25 与 40/10；10/40 下 burn 持平）   |
| ucb     | 810,074     | −13.0  | +5.7      | −2.27  | 双输               |

40/10 下排序一致（aimd0 exch +3.42、aimd100 +2.19 居前，AdamW/UCB 依旧双输）；10/40 下**全部自适应控制器 Δburn≤0**——重负载下这笔交易做不成，自适应只剩 miss 成本（与逐 rep 高方差叠加，见 §5.2.3）。两点推论：

- **AIMD 的吞吐优势集中在起点 100**。aimd100 在 25/25（1,031k）与 40/10（867k）都是吞吐最高、miss 最低的 AIMD 起点（6.8% / 6.7%，反低于 aimd50）：高起点把首个 L 段的爬升红利吃满，而乘性退避让它在 H 段付出的学费与低起点相同——AIMD 的鲁棒性（§5.2.3 图）在这里升级为「起点越高越赚」；
- **burn-miss 帕累托前沿上，自适应控制器占据中段全部席位**：25/25 前沿 = fixed25 ← aimd100 ← sgdm ← fixed50 ← fixed75 ← fixed100；40/10 前沿 = fixed25 ← aimd100 ← aimd0 ← fixed50 ← ⋯。高吞吐端是 static 高 α（miss 失控），低 miss 端是 oracle fixed25，**中间「吞吐与 miss 都尚可」的地带只有自适应控制器**。

**分相位账（吞吐从哪赚、miss 在哪付）**：以 25/25 aimd50 vs fixed25 计，L 段 ai 的 CPU 份额 +3.3pp（miss 仅 +3.2pp），H 段份额 −1.4pp（miss 却 +5.8pp）——吞吐红利几乎全部赚自轻负载段的冲高兑现，miss 账单大部分付在重负载段的悬崖逗留。这正是「轻载赚、重载退」策略的定量画像，也解释了为什么 exchange 为正的只有 AIMD 家族：它的退避足够快，把 H 段的逗留时间压到了最短。

**全场 21 模式定性：不是「其余都输光」，而是三个阵营**（25/25，相对 fixed25）：

| 阵营 | 代表（Δburn / Δmiss） | 说明 |
| --- | --- | --- |
| 吞吐赢家、miss 跳崖 | fixed50/75/100（+29~+60% / +39~+96pp）、三兄弟（+18.8~+27% / +30~+49pp）、cubic 全家、pid50 | 吞吐全部为正——它们没有输在吞吐轴，只是把 miss 卖到了 20~98% 的不可用区 |
| 双输 | adamw×3（25/25 与 40/10；10/40 下 burn 持平但 miss +22.5pp）、ucb、pid0/pid100、fixed0 | 吞吐为负、miss 还更高，被前沿甩开 15~24% |
| 划算交易 | AIMD 家族（+0.5~+10.7% / +3.2~+4.5pp） | 唯一在可用 miss 区（≤10pp）内做出正吞吐交易的控制器 |

「其他方法都输」只在**双输意义**下成立；更准确的说法是：其余方法要么用不可接受的 miss 换吞吐（第一阵营），要么两头皆失（第二阵营）。单边悬崖地形上吞吐随 α 单调递增，谁敢把 α 钉高谁吞吐就高——真正的难度不在赚吞吐，在于**不跳崖地把吞吐赚到手**，这正是 AIMD 家族独占「划算交易」阵营的原因（形式框架 §6.5、方差税 §6.6、AdamW 解剖 §6.7）。

![burn-miss 帕累托前沿](logs/sched/all/exp10_pareto_burn_vs_miss.png)

*图：全 21 模式的 burn-miss 平面（虚线 = 帕累托前沿，红星 = 后验 oracle fixed25）。AIMD 家族贴着前沿，AdamW/UCB/PI 全部落在前沿左下方的被支配区。*

## 6 分析：为什么 AIMD 赢

### 6.1 单边悬崖地形

miss 代价**全在高 α 一侧**：α 低侧几乎免费（地板 miss），α 高侧是悬崖（fixed50 即 42%，fixed100 达 98%）。任何控制器都要回答同一个问题：**以什么速度、从哪一侧逼近这条悬崖，以及逼近后是否逗留**。α=0 一侧是「安全但浪费吞吐」的平原，高 α 一侧是「吞吐富矿但会掉下悬崖」。

### 6.2 信号结构决定落点

| 缺陷                  | 后果                           | 受害者                     |
| ------------------- | ---------------------------- | ----------------------- |
| 信号吞吐盲（只罚 miss 不奖吞吐） | 安全区 reward 平台，无爬升梯度          | PI（饱和 0）、UCB（游走 6.7）    |
| 无 decay / 无先验       | 高 α 饱和高原上 Δloss→0 → 梯度消失，回不来 | 三兄弟（漂高 57~72）           |
| 无冻结 + 连续爬           | 逼近悬崖减速不成立，反复过冲               | CUBIC（抖动 46，miss 21.6%） |

**AIMD 是唯一把三个坑都避开的**：显式 +5 试探提供了「无错误时也会动」的吞吐方向；gray 冻结避免了在悬崖边缘逗留；乘性退避保证远离悬崖的速度。它不是「更聪明的优化」，是**更贴地形的先验**。

### 6.3 优化器家族的分裂：AdamW 为什么稳、三兄弟为什么拉垮

四个优化器共用同一 SPSA 梯度估计、同一 loss、同 lr=3，唯一差异是更新公式。但在这块地形上，公式差异**恰好在起作用的地方全部失效**：

- **安全区里，四个控制器同样瘫痪**。loss 是单边悬崖信号：安全窗 loss≈0、危险窗 loss 饱和封顶。两种情况下相邻窗 loss 差分 `Δloss≈0 → g≈0`——动量是对梯度信号的平滑放大，自适应归一是对梯度信号的尺度重整，**放大零还是零，重整零还是零**。g≈0 时三兄弟的 step 全部归零，公式差异失去意义。（混杂承认：危险窗侧的 Δloss≈0 有 loss 封顶 4000 的放大成分——miss 爆掉时 loss 触顶同样制造平台，「三兄弟漂高」里有多少来自 loss 设计、多少来自无 decay，本设计未做分离；但下文的同家族消融四者共用同一 loss，AdamW/三兄弟的分水岭不受该混杂影响。）
- **AdaGrad 的累积器把步长变成单向棘轮**。v+=g² 只增不减：早期振荡期的大梯度永久垫高 √v，后续步长被永久打折——即使偶有梯度也走不动。它在 25/25 的 α_steady 71.8 是全部 21 个模式之最。
- **AdamW 的 decay 是全场唯一不依赖梯度的力**。实现里 `decay = 2%×(target−α_f)`（target=25，即每窗把 α 往 25 拉 2%，时间常数 ~50 窗），经 `α ← α − step + decay` **加性注入**更新。loss≈0 的安全区里三兄弟 step→0 即原地冻结，decay 却照常发力——这不是「更好的优化」，是**把调度先验（α 应在 25 附近）直接编码进更新规则的恒稳力**。
- 同批对照进一步定位了各组件：RMSProp 与 AdamW 只差动量 + decay 两项，行为却天壤之别（51.0% vs 7.5% @25/25）——动量救不了信号缺失，decay 才是分水岭。

数据两面印证：(a) adamw 的 α_steady 在 3 起点 × 3 ratios 下全部回落至 21.5~30.6，围绕锚点 25——落点由先验决定（10/40 下 adamw100 miss 均值 16.8 反低于 adamw50 的 25.5，看似异常，实为高方差假象：该 ratio 下 adamw 单 rep miss 横跨 10.6~43.9%，均值排序不携带机制信息）；三兄弟落点 42~72，由「漂到哪算哪」决定，随 ratio 与起点漂移。(b) exp07 分量恒等式 `α(t+1)=α(t)−step+decay` 离线重放 2204 窗失配 0，且安全区 α−25 按每窗 2% 几何衰减——AdamW 的稳态归位可完全归因于 decay 项。

### 6.4 PID 为什么非单调：双吸引子 + 不可逆过冲

- **α=0 是钳位边界**：α=0 处迟到地板（唤醒排队延迟）> target=10 → e>0 永续 → 控制器想往下走但被钳住；
- **α≈36 是稳定平衡**：H 段 late_delta 恰好 ≈ target=10 → e≈0 → 不动。

pid100 从 100 出发，H 段首窗的 kp·Δe 冲量（−40~−60 点/窗）越过 α=36，直接砸穿到钳位边界 0，而 0 处无爬升信号，于是**永久停住**。pid50 的冲量小，恰好落在平衡点。**起点决定吸引子，且过冲不可逆——因为控制器在消灭误差的同时，也消灭了自己的驱动信号。** 这与 exp08 的「自毁信号」是同一机制的同批复现。

*图：同一个 PI 控制器的三种命运——pid100 在首个 H 段砸穿至钳位边界 0，pid50 滑入 α≈36 平衡点，pid0 贴地不动。起点决定吸引子。*

### 6.5 tradeoff 经济学的形式框架

§5.2.5 的四本账可以钉在地形的四个命题上：

- **P1 吞吐单调性**：burn(α) 随 α 单调不减。机制：scale(n,α)=⌊n^(α/100)⌋ 使 ai 有效票数随 α 单调，调度器 work-conserving → α 越高 ai 份额越高、完成的 burn 越多。fixed0→fixed100 扫描（exp02/exp10）实证单调。
- **P2 单边悬崖**：miss(α) 分两段——低 α 侧「地板区」（唤醒排队延迟决定地板，对 α 不敏感，几乎免费），高 α 侧「悬崖区」（ctrl 被饿死，miss 跳变至饱和）。量化（25/25）：fixed25 2.4% → fixed50 41.7% → fixed100 98.1%。
- **P3 静态前沿**：静态策略只有 1 个自由度 α，(miss, burn) 组合被 P1+P2 钉死在一条曲线上；后验 oracle = miss 预算下该曲线最便宜的点。自适应策略的自由度是 α(t)——一条时间函数，它的可达域取决于它吃掉这条曲线多少「时间结构」。
- **P4 相位经济学**：自适应的红利全部来自 α(t) 与负载相位的错位——**收益项** = Σ_L [burn(α_L) − burn(α_static)]（轻载段冲高红利），**成本项** = Σ_H [miss(α_H) − miss(α_static)]（重载段逗留代价）。exchange = 收益项/成本项 正是 P4 的量化形态：AIMD 用 +5 试探最大化收益项（L 段冲 60~97），用乘性退避 + gray 冻结最小化成本项（§5.2.5 分相位账：红利全赚自 L 段、账单大部分付在 H 段）。

**推论：三阵营是必然的**。P1-P4 之下任何控制器必居其一：住在高 α 区（阵营一：吞吐赢、miss 跳崖），住在低 α 区但带开销或抖动（阵营二：双输），或做成相位差交易（阵营三）。阵营三需要同时具备两个组件——「无错误也会动的推力」（收益项）与「有错误立刻停的刹车」（成本项）；§6.2 的信号结构论证正是 P4 的组件级分解。

### 6.6 方差税：同样的均值，三倍的 miss——但只在悬崖的凸侧

miss(α) 的地形（25/25，fixed 五点实测）：0→2.98%、25→2.37%、50→41.65%、75→83.04%、100→98.08%。悬崖边缘（25~50）急剧上跳、崖顶（50~100）增速放缓——**边缘是凸的，崖顶是凹的**。由 Jensen 不等式，α 的抖动在凸区加税、在凹区给补贴：`E[miss(α)] ≥ miss(E[α])` 仅对凸区成立。

**单点对照：同样的均值，三倍的 miss**（25/25 测量段窗口级）：

|      | α 均值 | α 标准差 | miss% |
| ---- | ----- | ------- | ----- |
| fixed25  | 25.0  | 0     | 2.4 |
| adamw50  | 25.7  | 17.6  | 7.5 |

均值几乎相同，把 adamw50 逐窗按生效 α 分桶：α<15 占 29.9%（miss 6.2%）、α≥40 占 21.8%（miss 9.6%）、中间带 6.2~7.5%。**税不集中在个别灾难窗口**——各桶 miss 均匀得反常，与静态地形应有的陡坡大相径庭，说明分布项是通过 miss 相对 α 的滞后兑现与相位混杂实现的；静态记账视角下：若把 adamw50 钉在它的均值 25.7，地形给出的 miss 只有 ~3.4%，Jensen 缺口 ≈ +4.1pp，加上均值偏移的 +1.0pp，配平观测的 +5.1pp。

**位置依赖的反例：AIMD 的抖动反而省钱**。aimd50 均值 41.8、std 21.2，钉在均值应 miss ~28.7%，实际只有 6.9%（Jensen 缺口 **−21.9pp**）——它 46.5% 的窗口住在 α≥40 的崖顶安全区（miss 仅 5.5%），抖动只把少数窗口甩下悬崖。这解释了为什么跨 16 个自适应模式做 miss 与 std(α) 的全局相关会得到近乎零的 r≈0.18：**方差税不是「抖多少」的函数，而是「在哪里抖」的函数**（散点图见 `exp10_vartax_miss_vs_jitter.png`）。

AdamW 的悲剧在于 decay 把它钉在 25——恰好是悬崖的凸缘，全地形税最重的位置；AIMD 的冲高则把驻留点推上凹的崖顶，同样的抖动从税变成补贴。AIMD 的 gray 冻结是另一层制度化对策：安全期完全停止 α 变化（25/25 全程仅 218 次 α 改变，AdamW 为 1,121 次），把驻留期的方差锁到 0。

### 6.7 AdamW 双输的四层解剖

AdamW 是唯一握有正确先验（decay→25）却落入双输的家族。注意与 §6.3 的关系：**「稳」不等于「赢」**——§6.3 的稳是落点的稳（α 归位 25），但 tradeoff 的账（§5.2.5）上它吞吐 miss 两头皆失。稳而不赢，恰是解剖的价值所在。逐层解剖（25/25，adamw50）：

1. **L 段推力真空（错过收益项）**。loss≈0 → g≈0 → step≈0（§6.3），轻载段 AdamW 推力为零，α 被 decay 牵着停在 ~25；AIMD 的 +5 试探则冲到 60~97。adamw 轨迹里的 max α=82 大多是起点 100 的下滑路径，不是主动爬升；
2. **CPU 分配赤字（收益项的账）**。ai_run 96.7k vs aimd50 的 107.6k（−10.2%）——不是 burn 效率差（burn/run 9.03 反而是全场最高档），是 CPU 分配本身少 10%；
3. **控制面开销（赤字的来源之一）**。1,121 次 set_sched_alpha/rep（AIMD 的 5.1 倍、fixed 的无穷倍），syscall + scale 整表重算全算在 ctrl 头上：ctrl 份额 39.4% vs fixed25 的 35.9%。与 exp04 Bug 2 同一机制——AIMD 靠 cooldown=3 / safe_windows≥2 把调用频率砍到 ~120 次/rep 才翻身；AdamW 的每窗 SPSA 结构连节流都做不到；
4. **悬崖边逗留（成本项的账）**。decay 时间常数 50 窗 + SPSA δ=±5 探针使 α 永远驻留在 25±15 的抖动带里、不时擦过悬崖边；叠加 §6.6 的方差税 → miss 7.5%。

一句话：**AdamW 有正确的先验，却是错误的身体**——decay 告诉它「应该住在 25」，SPSA 的每窗探针结构却迫使它「在 25 流浪」：流浪付出了控制面开销（吞吐 −6.2%），也付出了方差税（miss +5.1pp）。AIMD 的身体（冻结 + 冲高 + 退避）恰好相反：该不动时一动不动，该动时快。

### 6.8 综合

调度 α 的在线调节，本质是在**信息受限、单边代价、带噪声**地形上的在线决策问题。五类方法的落点差异可归约到两个维度：

1. **信号是否吞吐盲**（决定了「安全时会不会动」）；
2. **有无非零先验/探索**（决定了「有没有力把你从平坦/饱和区拉出来」）。

AIMD 的「阈值动作 + 显式试探 + 冻结」恰好是这两个维度的最优组合——它的胜利是**领域先验的胜利，不是算法复杂度的胜利**。

### 6.9 威胁有效性（limitations）

- **n=3 且无显著性检验**：主表只报均值。以 aimd50 vs adamw50（25/25）为例：miss 一项的误差棒有少量重叠（aimd50 6.5~7.6 vs adamw50 6.6~9.0），但吞吐区间完全不重叠（aimd50 938k~979k vs adamw50 843k~906k），双指标合看「AIMD 支配 AdamW」可辩护；而 10/40 的 miss 均值差（如 aimd50 19.5 vs adamw50 25.5）逐 rep 大幅重叠（10.8~36.0 vs 16.4~33.9）、统计上不可辩护，故本文只把 10/40 当方向性旁证（§5.2.3）；sgdm/rmsprop/adagrad 的大误差棒（如 sgdm burn +388k/−218k）如实报告，其均值排序不携带机制信息；
- **单核验证**：SMP=1，QEMU TCG 无真实并行，多核行为未验证；
- **负载空间有限**：3 种相位比例 × 固定幅度，未覆盖随机突变、多阶段；
- **超参未做敏感性分析**：lr=3、target=25、kp/ki、c_explore=1000 等；
- **单指标 loss 设计**：miss+late 的加权是设计选择；
- **QEMU 宿主干扰**：虽已标定 + 同批，绝对时间精度仍受模拟器限制。

## 7 相关工作

**按权重调度**：stride/lottery（Waldspurger & Weihl, 1994/1995）奠定按票分配框架；Linux CFS 用 vruntime 近似。本文的 α-scaled 是 stride 之上「随线程数缩放」的动态权重。

**α 公平性谱系**：Mo & Walrand 的 α-fair utility（2000）与无线 α-PF 调度用「速率/需求的幂次」在总吞吐与最大最小公平之间插值——与本文 `n^α` 数学形式同构，但作用对象（效用 vs 票数）、方向（α 大越公平 vs α 大越偏线程）、场景（网络 vs CPU）均不同。Stolyar（2004）的 MaxWeight-β 把「队列长度的幂次」做权重，是「需求量^可调指数」的又一邻居。

**按线程数调权重的先例**：Kay & Lauder（CACM 1988）最早指出「多开进程/线程能增大份额」的问题；TWRS（Thread Weight Readjustment Scheduler）用「线程数越多权重越低」的惩罚式线性来封顶——与本文的幂次奖励方向相反。本文的 `eff = tickets × n^(α/100)` 作为**内核里单一运行时可调参数**，在整条谱系中无直接先例，但各端点（fair-share 与按线程比例）均有成熟工业实现（cgroup cpu.shares / VMware ESX shares）。

**学习式调度**：Decima（Mao et al., 2019）等用强化学习做集群调度；本文将**无模型随机梯度（SPSA）**与**在线 bandit（UCB）**直接嵌入内核，在无浮点、无训练基础设施的环境下完成在线自适应，与「重模型」方法形成对照——本文的结论是：这类通用方法能站上同一舞台，但在单边悬崖地形上吃不到启发式的先验。

## 8 结论与展望

### 8.1 结论

基于 189 runs 的同批受控实验，本文得出：

1. **自适应调度问题的本质是单边悬崖地形上的在线决策**（§6.1）；
2. **五类方法家族的稳态落点由「信号结构 + 先验/探索」决定，与更新公式复杂度无关**（§5.2.2）——这是本文的核心表征；
3. **朴素启发式 AIMD 在自适应控制器内部帕累托最优**，梯度法/控制法/学习法均未超越（§5.2.3）：带 decay 先验的 AdamW 吞吐低 ~10% 且 miss 反高（双输），同家族无先验的三兄弟 miss 32~65%——家族内部的分裂本身就是「先验 > 复杂度」的证据。注意对比边界：后验 oracle fixed25 的 miss（2.4~3.5%）仍优于一切自适应控制器，自适应的价值在吞吐盈余与负载迁移，不在静态 miss；
4. **miss-吞吐 tradeoff 可定量**（§5.2.5）：exchange（每 1pp miss 换来的吞吐%）只有 AIMD 家族为正且最高达 +2.4，AdamW/UCB 双输；吞吐赚自 L 段冲高、miss 付在 H 段逗留；burn-miss 前沿的中段席位全部属于自适应控制器。其余方法并非全输：三兄弟与 cubic 的吞吐为正，但 miss 卖到 20~98% 的不可用区——在可用 miss（≤10pp）内做出正吞吐交易的只有 AIMD 家族；
5. **PI 的稳态与起点非单调**（双吸引子 + 不可逆过冲，§5.2.4），是「控制器亲手消灭自己的误差信号」的同批复现；
6. **方法学教训**：`ai_burn` 跨批次不可比，方法间对比必须以「同一批次 + burn/run QC」为前提（§2.6）。

### 8.2 展望

- **实机验证**：移植 VisionFive 2（JH7110，4×U74）复现核心对照，验证真实多核下的行为；
- **更丰富的目标**：per-process α、tardiness 误差信号、带吞吐项的 reward（直接检验 §6.2 的「吞吐盲」假设）；
- **更复杂的负载**：随机突变、多阶段、混合周期；
- **敏感性分析**：lr/target/δ/窗口长度/kp/ki/c_explore 的系统扫描。
