## 1. 模型与记号

负载 (exp2/exp4 同族): ctrl (T=300, n=1, period p, 每 job 需 cpu tick), ai (T=100, n_ai 线程),  
log (T=50, n_log=3)。α∈[0,100], x=α/100。

三层模型, 层层逼近实现:

| 层            | eff 公式                      | 出处                                                                       |
| ------------ | --------------------------- | ------------------------------------------------------------------------ |
| M1 连续理想      | T·n^x                       | 理论分析用                                                                    |
| M2 floor 实现  | T·floor(n^x)                | math.rs `sched_thread_scale` = floor(n^(α/100)).max(1), 二进制小数分解+定点 isqrt |
| M3 supply 修正 | 实际 share = min(线程供应, M2 份额) | §4 数据发现                                                                  |

**stride 份额引理** (Waldspurger 1995): 持续可运行进程 i 的长期 CPU 份额 = eff_i / Σ eff_j。  
本文所有 share 公式均建立在此之上。

**运行环境为单核** (exp1/exp2/exp4 每窗 run 总量均 ≈ 99-103 tick / 100 tick 窗,  
`account_current_tick` 每 tick 只给当前 running 线程 +1, 单核下每窗总和必 ≤ 100;  
实测 ≥ 99 说明除 ~1% 调度间隙外 CPU 无空转)。多核假设的全部推断作废。

## 2. 定理 1: 份额单调性 (M1/M2)

**陈述 (M1)**: share_i(x) = T_i·n_i^x / Σ_j T_j·n_j^x, 则

```
∂share_i/∂x = share_i · (ln n_i − Σ_j share_j·ln n_j)
```

即份额对 α 的单调性符号完全由"该进程线程数的对数是否超过全系统份额加权几何平均"决定。  
ctrl 单线程 (ln 1 = 0), 只要存在多线程进程, 其份额对 α 严格单调不降的对照组——ctrl 严格单调降。

**证明**: 对 ln share_i = ln T_i + x·ln n_i − ln(Σ T_j n_j^x) 求导, 第三项的分母导数  
恰为 Σ share_j·ln n_j。∎

**陈述 (M2)**: 实现中 scale = floor(n^x) 单调不降, 故 M2 份额 = T·floor(n^x)/Σ 仍是阶梯单调,  
且台阶位置在 n^x 跨过整数处。

### 2.1 数据验证 (exp1: 等票 100, n = 1/9/25, 单调机制层)

实测份额比 t2/t1, t3/t1 对照 (101 个 α 档):

| α   | t2/t1 实测 | floor(9^x) | t3/t1 实测 | floor(25^x) |
| --- | -------- | ---------- | -------- | ----------- |
| 10  | 1.007    | 1          | 1.000    | 1           |
| 30  | 1.010    | 1          | 2.015    | 2           |
| 50  | 3.018    | 3          | 4.968    | 5           |
| 70  | 3.986    | 4          | 8.815    | 9           |
| 100 | 9.058    | 9          | 23.901   | 25          |

101 档平均 |实测−理论|: **连续模型 0.542, floor 模型 0.162**。  
低 α 段 (α≤20) 实测恒为 1——连续模型预测 1.25~1.55 全部落空, floor 模型全中。  
**结论: 低 α 无放大不是噪声, 是整数因子的阶梯结构, 被数据逐档证实。**  
(α=100 的 t3 偏低 4.4%: 6000 tick 内 25 线程 stride 收敛残差, 属二阶项。)

### 2.2 数据验证 (exp2: 恒定负载 ctrl 份额)

α=100 (最大压迫) 时 M2 模型精确到千分位:

| config          | ctrl 实测 | 理论    | 误差    |
| --------------- | ------- | ----- | ----- |
| light (ai 7t)   | 0.261   | 0.261 | 0.000 |
| medlo (ai 15t)  | 0.137   | 0.136 | 0.001 |
| medium (ai 25t) | 0.094   | 0.092 | 0.002 |

而 α=0 (无压迫) 时理论 0.667, 实测全部 ~0.38-0.42——这不是模型失效, 是 §4 的供应天花板。

## 3. 定理 2: 临界 α* (充分条件版)

**陈述 (M2)**: 设 ctrl 需求 r = cpu/period。若 share_ctrl(α) < r 则 ctrl 必然丢截止期。  
share_ctrl(α) 随 α 单调降 (定理 1), 故存在临界 α\* 满足 share_ctrl(α\*) = r,  
α > α\* ⇒ miss。α\* 由 2·floor(n_ai^x)+floor(n_log^x) ≤ 2/r − 2 解出 (3 进程特例)。

**性质**: 这是**充分条件** (份额都不够必然 miss), 不是必要条件——§4 将用数据展示  
份额够时也可能 miss / 份额不够时也可能不 miss, 真实机制是唤醒排队延迟。

### 3.1 exp4 相位负载验证 (ai 50t 重相/5t 轻相, 数据实锤 ready=51)

fixed 各档 (3 reps 合并, 相位 L/H = 窗口 600 段等分):

| mode     | 相   | share(M1) | share(M2) | 实测ctrl | miss率             |
| -------- | --- | --------- | --------- | ------ | ----------------- |
| fixed0   | L/H | 0.667     | 0.667     | 0.381  | **3.0-3.1% (地板)** |
| fixed25  | L   | 0.582     | 0.667     | 0.383  | 3.7-3.9%          |
| fixed25  | H   | 0.475     | 0.545     | 0.383  | 3.5-3.8%          |
| fixed50  | L   | 0.492     | 0.545     | 0.346  | 11.0-31.9%        |
| fixed50  | H   | 0.274     | 0.286     | 0.346  | **97-100%**       |
| fixed75+ | 全   | ≤0.43     | ≤0.43     | ≤0.254 | 56-100%           |

读法:

1. **充分条件方向全对**: share 压到 0.55 以下 → miss 显著上升 (fixed50 起), 排序 L<H 一致。
2. **fixed25/H 反例**: M2 说 share=0.545<0.6 应违约, 实测 3.5%≈地板 → 份额够不够不是真实判据。
3. **AIMD 稳态标定真实临界带**: H 段 α 分布 p25=22 中位=27 → 系统真实"开始疼"的位置在  
   α≈25-50 之间, 高于 M1 (9.4) 和 M2 (17.7) 的预测。

### 3.2 exp2 的对应预测 (p=4, r≈0.675 > 基础份额 0.667)

基础份额已低于需求 ⇒ 理论预测**所有档从 α=0 就边际违约**。实测 (stat 表) light α=0 miss  
为低但非零——方向吻合, 量级由二阶项 (唤醒延迟噪声) 决定。

## 4. 修正发现: supply-limited 结构 (M3)

**现象**: exp4 fixed0 全段 ctrl 实测份额 0.381, 恒低于理论 0.667; ai/log 每 ticket 份额  
恰为 ctrl 的 3.2 倍。

**机制**: ctrl 工作线程烧 3 tick 睡 2 tick (周期任务), 40% 时间进程内**无任何可运行线程**。  
stride 只在 pick 时分配——无可运行线程的进程不参与 pick, 份额自动让渡。因此:

```
实际 share_ctrl = min(线程醒着的时长占比, M2 份额)
spin 组 (永远可运行) 按 eff 比例瓜分剩余: share_ai = (1−share_ctrl)·100/150
```

**验证 (fixed0, 3 reps 合并, 跳过前 50 窗启动期)**:

|     | 实测    | 剩余瓜分预测 |
| --- | ----- | ------ |
| ai  | 0.412 | 0.413  |
| log | 0.208 | 0.206  |

**误差 <0.002。** sleep 让渡 + spin 瓜分的结构被数据定量证实。

**对 miss 机制的含义**: ctrl 的 miss 不是"份额不够"而是"睡醒后排队等太久, job 在 period  
内烧不完"。α 增大 → ai eff 增大 → ctrl 睡醒后的排队延迟增大 → miss。  
这解释了 §3.1 的两个"反常": fixed25/H share 0.545 却不 miss (排队延迟尚小),  
fixed100/L share 0.19 尚可却 98.8% miss (排队延迟已灾难性)。  
(注: 内核 wake_blocked_thread 的"tickets≤1 才重置 pass"修复使高票进程睡醒不享有  
免费优先——这是排队延迟随 α 放大的结构根源。)

## 5. 定理 3: AdamW decay 漂移 (先验修正 + 待新数据验证)

**原陈述**: 安全区 (loss=0 ⇒ 梯度信号消失) 内, 更新由 weight decay 主导:

```
α_{t+1} − 25 = (α_t − 25)·(1−λ),  λ=2%/窗 ⇒ 时间常数 1/λ = 50 窗
```

**v1 数据的先验修正**: 用 exp6 v1 (ratio=250 首个 RUN) 的 A 行轨迹做了初步检验——  
miss=0 窗口 (692 个) 中 alpha 呈 28-47 的**有界波动** (44→28→47→29→…→47),  
ln(α−25) 回归斜率 ≈ 0, **不是几何衰减**。原因: ctrl 为 in-parent, late 基线  
非零, loss = miss + late 在 miss=0 时仍随 late 波动 → SPSA 弱梯度持续提供信号,  
"loss 纯平坦区"在该环境不存在。**定理 3 的原始形式只在 loss≡0 的环境成立**,  
v1 数据将其修正为: decay 是向 25 的系统性引力, 但与弱梯度随机游走叠加。

**新格式的检验方案** (A 行已扩展为 `A,win,before,after,action,loss,g,step,decay`,  
sl_policy_adamw 与 sl_policy_optim 同格式, 后者 decay≡0 作反事实):

1. **分量分解检验** (恒等式级): 逐窗 `α_f(t+1) = α_f(t) − step_t + decay_t`,  
   直接核对离线重放与 A 行一致。
2. **贡献分解检验** (统计命题): 全程 `Σ decay` vs `Σ step` 的净位移贡献对比——  
   预测 AdamW 的位置稳定性主要来自 decay 项; 三兄弟 (decay≡0) 在 miss=0 的  
   长段内 α 冻结或漂移 (若 step 残留动量非零) —— exp7 数据直接裁决。
3. **纯平坦区检验** (若存在 loss≡0 连续 ≥50 窗的段): 回归 ln(α_f/1024 − 25)  
   对窗口的斜率, 检验是否 ≈ −2%。

## 6. 勘误与已知偏差

1. **exp4 CSV 头注释 "ai=25t, light_active=3" 与实际不符**: W 行 ready=51 (alive 口径  
   n+1) 实锤 50 线程; 代码 (sexp4_dyn.c) 亦为 50t/5。注释漂移, 代码与数据一致。
2. **stat 口径**: W 行 ready_threads 用 count_alive (含阻塞主线程, n+1), eff 列为调度器  
   真值 (count_runnable 口径)。本分析用 eff 列, 不受 +1 影响。
3. **fixed50 的 L1 (11%) 与 L2 (32%) 同相位差 3 倍**: H1 灾难段后的 stride lag 恢复  
   残留, 未完全解释, 列为开放问题。
4. **α=100/t3 的 4.4% 低位偏差**: 短窗 stride 收敛残差。
5. 每窗 run 总量 ≈ 99-103 tick (单核, 上限 100): IDLE/调度间隙 ≈1%。

## 7. 与文献的关系

- stride 份额引理: Waldspurger & Weihl 1995 (lottery/stride)。
- "share ≥ utilization ⇒ real-time": EEVDF 一族 (Stoica 1995; Jeffay RTSS'96) 有明确  
  先例; 本系统 stride 的 lag bound O(n) 劣于 EEVDF O(quantum)——正是 §4 排队延迟的  
  文献级解释, 也说明本平台是 soft real-time 语义。
- floor(n^x) 因子的阶梯效应、supply-limited 让渡结构、decay 漂移定理: 未见先例,  
  归属本系统(因机制本身为本系统设计)。

## 8. 对 exp6-9 的可证伪预测

1. CUBIC: 若 miss 机制是排队延迟, CUBIC 与 AIMD 差异主要体现在"退避后逼近 w_max 的  
   减速"减少过冲次数, 而非 miss 率量级差异。
2. PI: 轻相位爬升 ≈ +0.6/窗 << AIMD +5/窗 → ratio=800 时 PI 的 ai 吞吐显著低于 AIMD。
3. SW-UCB: 无上下文 → 相位切换后 τ=32 窗内完成臂分布换血, 稳态臂应贴近各相位真实  
   临界带 (H≈25-50), 若它长期停在错误臂即证伪。
4. 优化器家族: 定理 3 预测三兄弟在安全区冻结, AdamW 几何漂移——A 行分解列直接可验。
